# Privacy and legal compliance map

> **Template - review with a lawyer before launch.** This is an engineering map of legal duties to code. It is not legal advice.

The Digital Personal Data Protection Act, 2023 and the DPDP Rules, 2025 (notified in November 2025, with staggered commencement) are the main law here. We built to them from day one. Each row names the duty, what the product does, and the code that does it. File paths are relative to the repository root.

| Rule | Implementation | Where |
| --- | --- | --- |
| Act only on the signed-in user's own application, with explicit per-run authorisation | Runs belong to one user; every server action checks ownership (`getOwnRun`). The worker fills only that user's confirmed profile. Each run needs its own authorisation tick (`authorized_at`). | `apps/web/lib/runs.ts`, `apps/worker/src/executor/executor.ts` |
| No bulk submission | One run at a time per worker; `MAX_RUNS_PER_USER_PER_DAY` (default 5) per user; idempotent final submit. | `apps/worker/src/loop.ts`, `apps/web/lib/runs.ts`, `apps/worker/src/executor/executor.ts` |

The model prompt forbids answering them and the validator only allows `request_human`. The demo OTP appears only in the applicant's checkpoint screen, never on a page the agent can load. ## Aadhaar

| Rule | Implementation | Where |
| --- | --- | --- |
| Do not collect, store or process Aadhaar numbers or Aadhaar OTPs | The demo uses a fictional Demo ID (`DEMO-1234-5678`). No field asks for Aadhaar; the upload screen and the ID-proof hint ask users not to upload an Aadhaar card. | `config/services/scholarship_demo.json`, `apps/web/messages/*.json` (`uploadAadhaarWarning`) |
| Detect and keep Aadhaar out | Aadhaar detection: 12 digits, first digit 2-9, valid Verhoeff checksum. PDFs with a text layer are refused at upload. Before the model reads a PDF's text, the worker checks again and deletes the file if it finds one; otherwise the text is masked. The extraction prompt tells the model never to output an Aadhaar number and to flag Aadhaar cards; a flagged document is deleted. Free text in logs and the audit log masks Aadhaar-like numbers. | `packages/shared/src/redaction.ts`, `apps/web/app/api/documents/route.ts`, `apps/worker/src/extraction.ts`, `apps/worker/src/llm/prompts.ts` |

## Honest limitations

- **Images cannot be scanned for Aadhaar before the model reads them.** We have no on-server OCR. A JPEG or PNG (or a scanned PDF with no text layer) goes to the model as it is, if the user gave AI permission. Mitigations: the upload screen and ID-proof hint warn against Aadhaar; the consent and Privacy Policy say so plainly; the extraction prompt tells the model to flag Aadhaar and return no values; a flagged file is deleted at once and its extraction marked rejected; users can decline AI and type their details.
- **The legal pages are templates.** They contain placeholder tokens (`[LEGAL_ENTITY_NAME]` and others) and show a template banner. A lawyer must review them, and the entity details must be filled in `config/brand.ts`, before launch.
- **The replay fixtures are hand-authored.** `fixtures/llm/agent-demo.json` uses the recorded format but was not recorded from a live model. To re-record, run the worker with `LLM_FIXTURES=record` and a real `ANTHROPIC_API_KEY`, complete a chaos-mode demo run, and review `fixtures/llm/recorded.json` before committing it.
- **Some data outlives `RETENTION_HOURS`:** the receipt PDF and receipt row, the redacted audit log, the consent ledger, and the practice portal's application row (tracking ID and hashes). They are deleted with the account.
- **Auth rate-limit keys hold the email address in clear** for up to 2 days (service role only).
- **Rules commencement.** The DPDP Rules commence in phases. Check which duties are in force on your launch date, and the exact text of the Rules in the Gazette.
